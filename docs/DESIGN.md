# 观潮 · 跨市场研究工作台设计哲学与架构演进

## 1. 文档说明

本文是「观潮」（Guanchao）跨市场投资研究工作台的**主设计叙事**：从原始需求，到早期落地、公开模板与开源仓、再到硬节点与反陈旧制度，说明每一层**为什么存在**、各部件如何咬合。它不是 changelog 罗列，也不替代 `BRIEF-CHECKLIST.md` / `SCHEMA.md` 中的现行硬规则。

- **读者**：维护本工作台的操作员、导入公开模板的使用者、以及审阅开源流程文档的贡献者。
- **As-of**：2026-09-25（Asia/Shanghai）。
- **边界**：描述研究流程与文件契约；不提供行情接口、不替券商下单。全文结论一律标注**非投资建议**。

配套公开入口：[GitHub `junit/guanchao-research-workbench`](https://github.com/junit/guanchao-research-workbench) · [Grok Bot 模板](https://x.ai/bot/nylU6e_GXKCzJvLLxN6qW)。

## 2. 原始需求

观潮要解决的不是「再做一个资讯聚合器」，而是：**在 A 股 / 港股 / 美股与宏观之间，按时段持续对照持仓与自选，把研究连续性写进可复查的档案**。

具体动机可还原为几条用户目标：

1. **跨市场、按时段**：盘前到收盘、隔夜到美股，各有固定窗口；不能只靠随手刷新闻。
2. **持仓与自选要被点名**：大事件、板块热度必须映射到具体代码与影响方向，而不是停在指数口号。
3. **研究要连续**：昨天的结论、证伪条件、近端日历，必须接上今天的证据；禁止只凭最新涨跌改判。
4. **拒绝噪音两种极端**：既不要把聊天刷成新闻流水，也不要堆 Yahoo/新浪抓取代码当「专业感」。
5. **机会与观察分流**：盘中可以标「观察候选」；真正进机会日志必须先有自洽深研。

一句话：观潮是**对照持仓的研究工作台**，不是行情播报员。

## 3. 核心设计原则

下列原则在各版本中保持不变；机制细节可演进，原则本身不因某次热点失效。

1. **持仓对照优先**  
   每次扫描先服务持仓 / 自选 / 候选的逻辑暴露；仓位数量可选（`positions.md`），缺失不阻塞判断。

2. **三层传导**  
   每个有意义的热点必须写清：市场（风险偏好 / 利率 / 油汇等）→ 板块与主题 → 持仓或观察池点名。禁止用一句「弱相关」打发。

3. **时间线累积改判**  
   简报含「上次结论 → 新证据 → 是否改判」。判断对照日历、标的档案与决策日志，禁止单日碎片拍板。

4. **研究优先再入库**  
   个股机会日志（`opportunity-log`）要求 thesis、催化、传导、财务核对与证伪自洽后才入库；时段简报不得直接追加。

5. **两档交付**  
   默认：聊天短档（决策卡若有 + 一句话 + 时间线改判 + 持仓要点）+ `briefs/` 全文。仅用户明确要求「全文」或例行写明时，才把全文推进聊天。

6. **说人话**  
   面向用户的标题、状态、期货与利率名称用自然中文；禁止把内部记号（如并集状态、路径名、抓取代码串）堆进正文。

7. **假日门控**  
   是否休市只查 `calendar/macro.md`（及交易所一手公告）。休市市场禁止编造 live 涨跌与板块热度；其它开市市场照写。

8. **决策告警有门槛**  
   高确信度机会或持仓重大风险才给出加仓观察 / 维持 / 减仓或规避等倾向，并写失效条件；日常波动静默。仍为非投资建议。

9. **流程与私人数据分离**  
   可公开同步的是清单、Schema、技能与空骨架；真实持仓、私有简报、深研正文与个人硬节点闹钟留在私有工作台。

10. **流程文档只写恒常规则；时效事件进日历**  
    Checklist / Schema / 例行 prompt 只固化机制与阈值（去重窗口、加密阈值、硬节点门槛等）。具体休市日、近端股东会、FOMC 时钟只存在于 `calendar/`、`portfolio.md` 与自删一次性例行。

## 4. 演进史

### 萌芽 / v0–v1：工作台落地

第一阶段把「对照持仓做时段研究」落成可运行目录，而不是散落聊天记录。

- **目录骨架**：`portfolio` / `tickers` / `sectors`（热度流水 + 主题卡）/ `briefs` / `alerts` / `calendar` / `research` / `sources` 等，用文件契约固定职责。
- **时段例行**：覆盖 A/港盘前到收盘、美股相关窗口，每次按清单扫大事件、指数与板块、再映射持仓。
- **简报硬门**：实时大事件不可跳过；无重大事件也须显式说明；传导三层与时间线段成为默认结构。
- **主题与热度分流**：`hot-log` 记流水连贯性；`themes/<slug>.md` 承载 why / 催化 / 证伪 / 风险 / 状态。
- **机会与观察分流**：盘中只进观察候选；深研自洽后再进机会日志。

这一层回答的是：**研究放在哪里、每时段必须写什么**。

### 加固期：架构盘点与修复

跑起来之后暴露的是一致性问题：主题卡与流水脱节、异动与时段简报重复推送、休市日仍假装交易、告警无留痕、地缘写成固定地区打卡表、机会日志被盘中热度污染。

加固措施包括：

- **主题状态硬门**：写完热度流水必须同步主题卡状态与最近复查；回吐则降温，持续退潮则归档。
- **异动与时段错开**：异动做相对上一简报的增量差量；与时段窗重叠时只写日志、不重复推送。
- **假日门控**：休市查日历，对应时段跳过或改短版，禁止编造该市场 live。
- **`alerts/LOG`**：每个异动窗至少一行（推送或未达门槛），形成可审计流水。
- **地缘动态时间线**：实时发现 → 沉淀 `global-hot-log` / `world-tracks` → 活跃 / 降温 / 归档；**无地区硬清单**。
- **research-first 机会日志**：强化「观察候选 → 深研 → 入库」门槛，并与板块机会索引分离。

这一层回答的是：**规则如何不被日常噪音冲垮**。

### 产品化 v2：公开模板 + 开源仓

当流程在个人工作台稳定后，需要把**可复用的流程**与**不可公开的私人数据**切开。

- **说人话与中文品名**成为默认：短档与全文面向人类阅读，而非内部操作员笔记。
- **两档交付**写入清单与 Schema，成为模板默认行为。
- **开源仓** [`junit/guanchao-research-workbench`](https://github.com/junit/guanchao-research-workbench) 发布清单、Schema、主题卡模板、告警规则、建议例行与空 `market/` 骨架。
- **Grok Bot 公开模板** [https://x.ai/bot/nylU6e_GXKCzJvLLxN6qW](https://x.ai/bot/nylU6e_GXKCzJvLLxN6qW) 负责「跑起来」：入门问答、例行、技能与可公开记忆。
- **明确不同步**：持仓实盘、私有简报全文、深研正文、仓位与个人闹钟不进公开仓与模板。

这一层回答的是：**别人如何 fork 流程，而不拿走你的仓位**。

### 制度升级 v3：硬节点、去重与反陈旧

v3 处理的是「例行很多，但关键节点仍漏」以及「流程文档自己会过期」两类制度问题。

- **加密旁证嵌时段**：比特币 / 以太坊随每个 A/港/美时段轻量刷新仪表；**不另开 24 小时独立 cron**。短档默认一行，达阈值或硬新闻才升格大事件；as-of 超过约 6 小时必须重刷。
- **硬节点三层**  
  1) 确认日期或可执行时间窗 → 默认进日历，靠晨扫与时段 T-3 覆盖；  
  2) 同时满足「确认窗 +（持仓一阶/改判 **或** 风向级叙事）+ 现有例行空档」→ 挂**一次性**盯盘，跑完或过期自删；时段已覆盖则不叠挂；  
  3) 宽窗口、未确认时钟、已归档主题、普通新闻 → **禁止虚挂**。
- **短档 ±40 分钟去重**：同一时段窗内后到者只更新全文并差分，聊天默认静默，有实质增量才补一句。
- **预约披露日强制升格**：宽窗口一旦出现精确预约日，同窗改日历、评估第二层闹钟、更新证伪近端索引。
- **反陈旧架构**：Checklist / Schema 禁止粘贴会过期的节假日或近端标的举例；时效只进日历与自删例行。
- **异动时钟单一真相源**：时刻以已启用「异动与证伪快检」例行为准，改 cron 须同窗改 `alerts/RULES.md`，禁止第二套钟。
- **仪表盘代码仅操作员可见**：`dashboards/INDEX` 可列抓取代码；用户可读简报只用中文品名。

这一层回答的是：**关键节点如何准时、文档如何不自腐、推送如何不刷屏**。

### 现状（2026-09-25）

当前个人工作台与公开模板在**流程层**对齐，在**数据层**分离：

- **例行网格**：A/港/美时段简报 + 美股盘后；工作日晨间「事件与证伪扫描」；工作日 10:22 / 13:22 / 15:22 异动快检；周一宏观周历、周五周报、月初月报；工作日下午机会深研队列（详见公开 `docs/ROUTINES.md`）。
- **个人硬节点闹钟**与公开模板分离：近端公司或风向级一次性例行只存在于操作员侧日历与自删例行，不写入公开仓名单。
- **工作台仍在跑**：假日门控短版、加密嵌时段、两档交付、主题 status 硬更新、alerts 流水等机制已落地；宏观周历 / 周报 / 月报等已配置，正式首跑与闭环以 `GAP-AUDIT.md` 开放项为准。

## 5. 系统如何运转（心智图）

用一条流水描述一次典型触发：

1. **触发**：例行 cron（或手动补跑）按 `Asia/Shanghai` 时段开火。  
2. **读入**：`BRIEF-CHECKLIST`、`SCHEMA`、`portfolio` / `tickers`、`calendar/`（含休市与近端事件）、相关主题与仪表盘。  
3. **扫大事件**：无地区偏置地检索本窗真正在热的宏观 / 地缘 / 政策 / 持仓公告；对照全球热点时间线做新增、延续或降温。  
4. **三层传导**：市场影响 → 板块与主题（写热度流水并同步主题状态）→ 持仓 / 自选 / 候选点名。  
5. **写全文**：结构化写入 `briefs/`，含时间线改判与回写清单。  
6. **短档聊天或静默**：默认推短档；若 ±40 分钟内已交付过同窗短档，则差分后默认静默；未达异动/决策门槛则异动窗也可静默。  
7. **回写**：`sectors/hot-log` 与 themes、`calendar/global-hot-log` 与 `world-tracks`、`dashboards/`、`alerts/LOG`、必要时 `journal/decisions` 与证伪表。

假日门控插在第 2–4 步之间：休市市场跳过 live 指数与板块，或改写「开市市场 + 全球 + 持仓映射」短版。加密旁证嵌在各时段刷新，不单独成一条 24h 主线。

## 6. 目录与职责一览

- `BRIEF-CHECKLIST.md` — 时段 / 快检硬门槛（含两档、假日、硬节点、去重、加密旁证）。  
- `SCHEMA.md` — 文件契约与生命周期。  
- `portfolio.md` / `positions.md` — 持仓·自选·候选索引；仓位可选。  
- `tickers/<code>.md` — 单标的 thesis / 催化 / 证伪 / 风险 / 状态。  
- `watch-candidates.md` / `opportunity-log.md` / `pending-delete.md` — 观察池、已深研机会、待移出。  
- `sectors.md` + `sectors/hot-log.md` + `themes/` + `opportunity-log.md` — 板块中枢、热度流水、主题卡、板块机会索引。  
- `briefs/` — 时段全文落盘。  
- `calendar/` — 宏观、公司事件、证伪、全球热点时间线与轨道。  
- `research/` + `sources/` + `comps/` — 深研、一手材料、可比草图。  
- `dashboards/` — 利率外汇 / 商品 / 加密 / 资金 / 一致预期等跨资产仪表。  
- `alerts/RULES.md` + `LOG.md` — 异动与决策告警规则及流水。  
- `reviews/` — 周报 / 月报。  
- `journal/decisions.md` — 升级、降级、入库、决策倾向留痕。  
- `GAP-AUDIT.md` — 带时点的缺口快照（非现行规则说明书）。  
- `DESIGN.md` — 本文：设计哲学与演进叙事。

公开仓对应的是上述**流程文档 + 空骨架**；私有工作台才填真实档案。

## 7. 例行职责分层

| 层级 | 职责 | 典型行为 |
|------|------|----------|
| **时段简报** | 该市场窗口的完整研究闭环 | 大事件 → 传导 → 全文 + 短档；假日门控；加密轻刷 |
| **异动与证伪快检** | 相对上一简报的增量差量 | 命中才推；与时段重叠则只写 LOG |
| **事件与证伪晨扫** | 近端日历与硬节点对账 | T-3 倒计时；补挂/删除第二层一次性闹钟 |
| **硬节点一次性** | 确认窗上的公司检查点或风向级事件 | 到点核一手 → 回写 → 达门槛才告警 → 自删 |
| **机会深研队列** | research-first 深潜 | 观察候选升级为自洽报告后才入库 |
| **周历 / 周报 / 月报** | 宏观刷新与正式复盘 | 回写 `macro.md`、reviews，并对照 GAP |

各层不互相替代：时段负责面，异动负责尖，硬节点负责钉，深研负责厚，周月报负责纵深。

## 8. 公开 vs 私有边界

**可同步到开源仓与公开模板（流程层）**

- `docs/` 清单、Schema、主题卡模板、告警规则、建议例行说明  
- `skills/` 入门与研究台技能正文  
- `market/` **空骨架**与标明 EXAMPLE 的占位  
- 说人话、两档交付、假日门控、硬节点机制、加密嵌时段等恒常规则  

**必须留在私有工作台**

- 真实持仓、自选、仓位与暴露图细节  
- 私有 `briefs/` 全文、深研正文、一手摘录中的敏感笔记  
- 绑定个人持仓的硬节点一次性闹钟名单  
- 券商密钥、付费行情账号、任何可识别个人账户的材料  

模板导入复制的是档案名、技能、例行与可公开记忆，**不会**带走原作者实盘。

## 9. 刻意不做的事

- **不做**独立 24 小时加密刷屏 cron；加密嵌在各股权时段即可。  
- **不做**时段已覆盖同一窗时再叠挂硬节点一次性例行。  
- **不做**把 Yahoo / 新浪抓取代码串堆进聊天或全文当「行情表」。  
- **不做**仅凭时段热度把个股写入机会日志。  
- **不做**地缘固定地区打卡表（中东 / 俄乌 / 台海等每次必勾）。  
- **不做**在 Checklist / Schema / 例行 prompt 里粘贴会过期的节假日或近端标的举例。  
- **不做**未达门槛的「无变化」刷屏；异动无命中可静默，但 LOG 仍记一行。  
- **不做**编造未确认的精确财报日、股东会日或休市 live 行情。  
- **不做**把公开仓当成持仓备份盘。

## 10. 后续演进建议（可选）

以下为轻量、可核对的机制向建议，不设虚构指标：

1. **宏观周历 / 周报 / 月报**：配置已在，优先完成正式首跑与回写闭环，避免「例行空转」。  
2. **下一开市日强制板块 live + 主题状态硬更新**：休市短版之后，开市日恢复完整传导。  
3. **宽窗口等待预约披露精确日再升格**：不编造日期；出现精确日则走强制升格流程。  
4. **OSS 与公开模板 lockstep**：只同步流程文档与技能；私人数据永不入库。  
5. **仪表与一致预期**：只回填可核验公开源；接口长期空值则保持「待填」，不伪造。

具体近端名单与时钟仍以 `calendar/` 与已启用例行为准，本文不枚举。
